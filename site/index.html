1. Filosofia e Licenciamento

O GOST orienta a criação de software livre com clareza jurídica e técnica desde o primeiro commit.

Presunção Padrão: Unlicense

Todo repositório deve presumir dedicação direta ao domínio público (The Unlicense ou CC0-1.0), eliminando atrito para cópia, reuso e evolução coletiva.

Exceção Copyleft: GPLv3

Projetos com salvaguarda explícita contra mercantilização predatória ou fechamento de código adotam a GNU GPLv3.

2. Anatomia Mínima da Raiz

Todo repositório aderente à especificação mantém uma base uniforme previsível:

.
├── LICENSE / UNLICENSE         # Licença declarada (Unlicense como padrão)
├── VERSION                     # Versão SemVer pura em texto simples (ex: 0.1.0-dev.1)
├── CHANGELOG.md                # Histórico no padrão Keep a Changelog
├── README.md                   # Resumo executivo e instrução de partida
├── .gitignore                  # Regras de higiene de arquivos
├── site/                       # Portal estático de documentação pública
│   ├── index.html              # Interface de visualização da documentação
│   └── _headers                # Cabeçalhos HTTP de segurança obrigatórios
└── .forgejo/ / .github/        # Workflows declarativos de CI/CD
    └── workflows/ci.yml

3. Ciclo de Desenvolvimento (DD-TDD)

Nenhuma alteração é iniciada ou finalizada sem rastreabilidade. O fluxo formal divide-se em 5 etapas sequenciais:

1
Ticket / Issue

Abertura do ticket formalizando o problema, a nova funcionalidade ou refatoração no issue tracker.

2
Doc in Develop (Commit de Documentação)

Formalização prévia do comportamento e interfaces esperadas antes de codificar.

docs: specify auth endpoint contracts (ref #42)
3
Failing Test (Commit do Teste Quebrado)

Criação do teste automatizado reproduzindo o bug ou atestando a falta da feature. O teste deve falhar.

test: add failing integration test for token expiration (ref #42)
4
Fix / Implementação (Commit do Código)

Desenvolvimento da solução estritamente necessária para fazer o teste passar.

feat: implement token expiration validation (ref #42)
5
Finish Docs & Close (Commit de Fechamento)

Revisão final dos guias, atualização do changelog e encerramento do ticket.

docs: update authentication documentation (closes #42)

4. Vitrine Pública e Segurança

Todo projeto mantém seu portal estático publicado via pipeline de CI. O arquivo site/_headers deve assegurar:

/*
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin

5. Perfil de Implementação: Lumen

O ecossistema Lumen implementa a norma GOST com os seguintes serviços e convenções:

  • Forja Principal: Codeberg (instância Forgejo) sob lumenpink/<repo>.
  • Gestão de Hooks: CLI cccp com validação de Conventional Commits e controle de versão.
  • Hospedagem Web: Cloudflare Workers via wrangler.jsonc servindo subdomínios *.2lp.in (com fallback no Codeberg Pages).
  • Descoberta: Registro no catálogo centralizado local ~/src/catalog.json.

Consulte o documento completo em profiles/lumen.md no repositório.
